# نظام حجز مرضى النواظير — مستشفى الجهاز الهضمي والكبد، النجف الأشرف

تطبيق ويب (واجهة + خادم Node.js/Express + قاعدة بيانات PostgreSQL) لحجز مرضى مناظير المعدة والقولون، جاهز للنشر على **Railway** برابط عام.

---

## 1) تجربته محلياً (اختياري)

```bash
npm install
# ثم عدّل DATABASE_URL في .env بمعلومات أي قاعدة postgres عندك (أو تجاهل هذه الخطوة وانشره مباشرة على Railway)
npm start
```

سيعمل على `http://localhost:3000`.

---

## 2) رفع المشروع إلى GitHub

Railway ينشر عادة من مستودع GitHub. إن لم يكن لديك حساب GitHub:

1. أنشئ حساباً مجانياً على github.com
2. أنشئ مستودعاً (Repository) جديداً فارغاً، مثلاً باسم `najaf-endoscopy-booking`
3. من داخل مجلد المشروع على جهازك:
```bash
git init
git add .
git commit -m "نظام حجز النواظير"
git branch -M main
git remote add origin https://github.com/USERNAME/najaf-endoscopy-booking.git
git push -u origin main
```

---

## 3) النشر على Railway

1. افتح **railway.app** وسجّل الدخول (يمكن الدخول مباشرة بحساب GitHub)
2. اضغط **New Project** → **Deploy from GitHub repo** → اختر المستودع الذي رفعته
3. سينشئ Railway "Service" لتطبيق الـ Node.js تلقائياً ويكتشف `npm start` من `package.json`

### إضافة قاعدة البيانات (PostgreSQL)

4. داخل نفس المشروع في Railway، اضغط **+ New** → **Database** → **Add PostgreSQL**
   سيظهر لديك الآن خدمتان في المشروع: تطبيقك، وقاعدة البيانات (Postgres)

### ربط قاعدة البيانات بالتطبيق

5. افتح خدمة التطبيق (وليس قاعدة البيانات) → تبويب **Variables**
6. اضغط **New Variable** → اختر **Add Reference** (أو اكتب يدوياً):
   - الاسم: `DATABASE_URL`
   - القيمة: اربطها بمتغيّر `DATABASE_URL` الخاص بخدمة Postgres (Railway يعرضه لك للاختيار مباشرة من قائمة، عادة باسم `${{Postgres.DATABASE_URL}}`)
7. احفظ — سيُعاد نشر التطبيق تلقائياً، وعند التشغيل سينشئ الجدول المطلوب في قاعدة البيانات تلقائياً (الكود يفعل ذلك بنفسه، لا حاجة لأي أمر SQL يدوي)

### الحصول على رابط عام

8. داخل خدمة التطبيق → تبويب **Settings** → قسم **Networking**
9. اضغط **Generate Domain**
   سيعطيك Railway رابطاً عاماً شبيهاً بـ:
   `https://najaf-endoscopy-booking-production.up.railway.app`

هذا هو الرابط الذي تشاركه مع موظفي الاستقبال — يفتح من أي جهاز متصل بالإنترنت (حاسوب أو موبايل)، وكل من يفتحه يرى نفس الحجوزات مباشرة من قاعدة البيانات.

---

## 4) بعد كل تعديل مستقبلي

أي تعديل تريده لاحقاً (مثلاً تغيير أسماء الأطباء أو الأعداد المسموحة):
```bash
git add .
git commit -m "وصف التعديل"
git push
```
Railway سينشر النسخة الجديدة تلقائياً خلال ثوانٍ.

## بنية المشروع

```
najaf-endoscopy-app/
├── server.js          ← الخادم (Express) وواجهات API وإنشاء جدول قاعدة البيانات تلقائياً
├── package.json
├── public/
│   └── index.html      ← واجهة الحجز (نفس التصميم، لكن متصلة الآن بقاعدة بيانات حقيقية عبر API)
├── .env.example
└── README.md
```

## ملاحظات

- قواعد السعة (12 منظار معدة، 8 منظار قولون، الجناح العام 3) مطبّقة في الخادم أيضاً وليس فقط في الواجهة، لمنع تجاوز السعة حتى لو استخدم عدة موظفين النظام في نفس اللحظة.
- إن ظهرت مشكلة اتصال بقاعدة البيانات تتعلق بـ SSL، أضف متغيّر بيئة `PGSSL=true` في إعدادات الخدمة على Railway.
- يمكنك تعديل أسماء الأطباء وتوزيع الأيام من داخل `public/index.html` (مصفوفة `DAYS` في أعلى قسم `<script>`)، وتعديل حدود السعة من نفس الملف (`LIMITS`) **و** من `server.js` (نفس اسم المتغيّر) حتى يبقى التحقق متطابقاً بين الواجهة والخادم.
